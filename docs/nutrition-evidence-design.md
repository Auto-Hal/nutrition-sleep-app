# 栄養評価の欠損データ対応設計

更新日: 2026-10-25

## 決定

**方式Eとして、既知量の表示（B）と欠損に伴う範囲の評価（D）を併用する。自動補完（C）は実施しない。** 完全データだけの従来評価（A）は互換性のため残すが、新しい画面・見直し判断は明示的な evidence を使う。

目的は評価可能日数を増やすことではない。記録から分かる量を失わず、不明な寄与があっても成立する比較だけを示し、成立しない比較を保留にする。食事記録、栄養値の充足状態、登録値の品質、基準との比較結果を別々に扱う。

ここでいう「下限」は、**記録した食事と登録値の正確さを条件とした、欠損に関する算術上の下限**である。分析誤差、食品成分の個体差、申告誤差、量の入力誤差を含む実際の摂取量の保証値でも、統計的信頼区間でもない。推定値を含む可能性が解消されていないデータから、医学的な確定判定はしない。

## 根拠と適用範囲

厚生労働省の2025年版は EAR、RDA、AI、DG、UL を異なる目的の指標として定義し、習慣的摂取量と日間変動を考慮した活用を求める。AI 未満から不足の有無やリスクは判断できず、EAR 未満を欠乏症と同一視できない。今回の表示は観察した記録の比較であり、個人の栄養状態や習慣的摂取量の確定評価ではない。[MHLW 2025 総論、冊子pp.30–35](https://www.mhlw.go.jp/content/10904750/001316460.pdf)

FAO は、食品成分値の欠損を0にせず利用者へ知らせること、補完した値の型と出典を文書化することを明記している。明示された0、trace、欠損は異なる。食品を補完元へ照合する場合にも、食品の特徴、調理状態、成分定義、単位、可食部等の分母を確認する必要がある。[FAO Food Composition Data, Chapter 9](https://www.fao.org/4/y4705e/y4705E14.htm)、[FAO/INFOODS Guidelines for Food Matching](https://www.fao.org/4/ap805e/ap805e.pdf)

IOM は個人の観察平均、日間変動、必要量の不確実性を区別し、食事データだけから個人の栄養状態を正確に判定できないと説明する。NCI の通常摂取量モデルも主に集団の分布を対象とし、個人の通常摂取量を正確に推定する手法ではない。本変更では小さな日数閾値を科学的確実性へ読み替えたり、集団向けモデルを個人へ移植したりしない。[IOM, Applications in Dietary Assessment, Chapter 3](https://www.nationalacademies.org/read/9956/chapter/8)、[NCI Usual Dietary Intakes](https://epi.grants.cancer.gov/diet/usualintakes/index.html)

以下の区間計算は、これらの資料が直接規定するアルゴリズムではない。非負の栄養量と欠損を区別する原則から導く、本アプリの保守的な実装判断である。

## 現状と原因の切り分け

`get_nutrition_daily_summary` は栄養値のスナップショットを日・栄養素別に集計する。`known_amount` は非NULL値の小計であり、`coverage_complete=false` の日に実摂取量の総量を表さない。`eligible_for_reference` は食事記録の完了と栄養値欠損の不在を要求する。`analytics.ts` の従来の基準評価は、その条件を満たす日だけの平均を使う。`known-intake.ts` は別に観察できた日の既知分平均を返す。

このため、毎日一部の栄養値が欠ける栄養素では、既知の小計が毎日存在しても従来評価の対象日は0となる。また栄養素ごとに完全日が異なり、完全日のみの平均は食事内容の異なる日を選ぶ可能性がある。栄養値の欠損がランダムだと仮定する根拠はない。

| 原因 | 意味と扱い |
|---|---|
| 1. 食事そのものが未登録 | 栄養値欠損と分け、食事記録未完了として数える。未登録食を0摂取とはしない |
| 2. 食品は登録済み、栄養値不明 | 欠損食品数・部分日・全不明日へ反映する。既知小計は残す |
| 3. 成分表にはあるが未登録 | NULLだけでは2と区別できない。食品と単位等の照合を経て確認する必要がある。今回の集計で存在を推測しない |
| 4. 信頼できる推定値はあるが確定値なし | 推定方法・出典・品質を確定値から区別すべき状態。今回、新しい補完値は作らない |
| 5. 含まないことが確認済み | 明示0を既知値として集計できる。測定限界やtraceの意味を勝手に変更しない |
| 6. 含まないと推測されるだけ | 無根拠な0への変換をしない。妥当な推定を導入する場合も、推定であることと由来を保持する |
| 7. 単位・栄養素定義・測定対象の不一致 | 数値があっても基準と比較可能とは限らない。変換根拠のない比較をしない |

7/30/90日の実態調査用に `supabase/audit/nutrition_evidence_coverage_readonly.sql` を用意する。これは READ ONLY トランザクション内で期間・栄養素ごとの集計件数だけを返す。ユーザーID、食品名、日付、摂取量を返さない。食品数は別々のカタログ食品数ではなく、摂取記録上の食品出現回数である。完全日、部分日、全不明日、空の完了記録、未完了日を区別する。接続できない環境の件数を推測したり、合成データの件数を本番実測として報告したりしない。

## A〜Eの比較

ここでの評価は、このアプリの現在のデータと運用条件に対する設計判断である。Cの品質は補完元と照合方法に依存する。

| 比較基準 | A 完全日のみ | B 既知小計 | C 推定・補完 | D 範囲・不確実性 | E 今回のB＋D |
|---|---|---|---|---|---|
| 栄養学的妥当性 | 完全日の記録比較として成立、選択日への限定が必要 | 小計として有効、総量扱いは不適切 | 適合した出典と方法が必要 | 登録値を条件とした部分的な比較が可能 | 小計と成立する比較を分けて提示 |
| 誤った不足判定 | 選択日の偏りが残る | 小計を総量扱いすると高リスク | 過小補完で発生し得る | 上限不明なら不足側を保留できる | 部分データでEAR未満等を断定しない |
| 誤った安全・適正判定 | 完全日だけの結果を期間全体へ広げるリスク | 小計がUL/DG上限未満でも安全とはいえない | 過小・過大補完で両方向に発生し得る | 範囲全体が条件を満たすときだけ比較できる | 到達と上限未超過・適正を分離 |
| 欠損への耐性 | 低い、毎日欠損なら0日 | 高いが情報の範囲を誤解しやすい | 高いが適切な照合先が必要 | 高い、情報不足は保留として残る | 全完全日0でも既知情報と参考事実を保持 |
| 食生活の代表性 | 完全日の食品構成に偏り得る | 共通の記録日集合なら選択を減らせる | 欠損を減らすが照合の偏りが残る | 共通日集合で扱えるが未記録の偏りは残る | 記録完了日を共通分母にし、期間外への一般化をしない |
| 実装・運用コスト | 小さい | 小さい | 高い、照合・品質審査・更新管理が必要 | 中程度、区間と理由の管理が必要 | 中程度、新しい外部依存・本番補完なし |
| UIの理解しやすさ | 単純だが0日表示が有用情報を隠す | 既知分の説明は容易、誤解防止が必要 | 推定の説明が必要 | 範囲と保留の説明が必要 | 主表示は量・基準・参考/保留、詳細へ件数を置く |
| 追跡可能性 | 完全日まで追跡可能 | 既知値・欠損まで追跡可能 | 出典・方法の追加管理が必須 | 端点・日集合・保留理由を追跡可能 | 従来値とevidenceを分離し、食事内訳へ接続 |
| 食品検索・AI推定との整合性 | 推定の扱いが別途必要 | 推定と確定の混同を避ける設計が必要 | 由来のある値を取り込める | 推定範囲があれば将来拡張可能 | 推定の有無を独立軸に残し、今回未解決と明示 |

Aだけを主方式にする案は、有用な既知情報の廃棄と日選択の問題から却下する。Bだけを通常の総摂取量比較に使う案は、不足・安全両方向の誤判定から却下する。Cを今回の解決の前提にする案は、照合と出典品質の確認なしに確定値を作れず、既存記録の一括変更も禁止されているため採用しない。有限上限を根拠なく作るDも採用しない。B＋Dは、保存値を変えずに既知情報を使い、成立する比較だけを増やせる。

## 日集合と平均の意味

対象期間はユーザーのタイムゾーンにおける7/30/90暦日。日別の食事記録完了は、既存RPCによる朝・昼・夕の recorded/skipped の定義を維持する。

期間の evidence 分母 `days` は、**食事記録が完了し、摂取項目が1つ以上ある日**の数とする。同じ食事記録完了日集合を使い、対象栄養素が全不明の日も分母に含める。これにより、栄養素の完全性を理由として日を選び直さない。空の完了記録は `empty_days`、食事記録未完了は `incomplete_record_days` として区別し、0摂取日として平均へ混ぜない。

この集合内で `complete_days + partial_days + unknown_days = days` とする。`complete_days` は全食品の対象値が判明した日、`partial_days` は既知値と欠損が混在する日、`unknown_days` は使える既知値がない日。明示0は既知値なので、0だけが記録された完全日は `complete_days` に入る。

`observed_days` は使える既知値が1件以上ある日数。従来の `record_average_known_amount` は、観察できた日だけで割った既知分平均として意味を維持する。一方、新しい `evidence.lower` は全 `days` を分母とする期間下限である。両者を同じ「期間平均」として表示・比較しない。

合成例として、4記録完了日の既知小計が80、100、120mg、全不明だった場合、観察できた3日での既知分平均は100mg、4日集合の算術下限平均は75mgとなる。全不明日の未知の寄与は非負なので、下限の和へ0を加えるだけであり、食品の値もその日の真の摂取量も0へ補完していない。4日すべて全不明なら、表示に使う `lower` はnullとし、「0mg摂取」と表示しない。

日別表示は当該1日を同じルールで計算する。期間結果は日別ラベルの多数決ではなく、同じ日集合の記録量の和から導く。日別の到達日数を完全データ日数へ読み替えない。

`evidence_daily` は各日について直接量・エネルギー比の範囲と比較結果を返す。`evidence_decisive_days` はRDA/AI等・DG・ULごとに比較が成立する日数であり、登録値を条件とする数学的な比較の件数である。医学的確信度や完全データ日数ではない。日別に到達した日が複数あっても、期間平均で到達するとは限らない。

## データモデルと互換性

各栄養素に `evidence` と `percent_energy_evidence` を追加する。

| フィールド | 意味 |
|---|---|
| `lower`, `upper` | 登録値を条件とした範囲。`lower:null` は使える観察なし。`upper:null` は有限上限不明であり0ではない |
| `dates`, `days` | 算出に用いた日付集合とその件数 |
| `observed_days`, `complete_days`, `partial_days`, `unknown_days` | 観察の有無と栄養値の充足状態 |
| `empty_days`, `incomplete_record_days` | 食事記録に関する別の状態 |
| `known_entries`, `missing_entries` | 当該日集合の既知・欠損食品出現回数。栄養量への寄与率ではない |
| `quality` | `user_verified` / `contains_unverified` / `unknown` / `not_applicable`。充足状態や医学的確信度とは別軸 |
| `estimate_status` | 今回は `not_resolved`。既存登録値に推定値がないと確認した意味にはしない |
| `imputation` | 今回は `none`。この集計処理が新しい値を補完しないことだけを示す |
| `basis` | `complete` / `partial` / `none`。データの揃い方を示し、検査精度や栄養状態を保証しない |
| `reasons` | 栄養値欠損、観察なし、不正な登録量、エネルギー欠損、品質未解決等の機械可読理由 |

比率の evidence は必要に応じ `energy_known_entries` / `energy_missing_entries` も保持する。直接量と比率は各々の対象日集合と必要データを持つ。

`evidence_dri.direct_evaluation` と `evidence_dri.percent_evaluation` は、それぞれ `adequacy`、`target`、`upperLimit`、`basis`、`uncertainty` を持つ。部分範囲から確定できない指標はnullを返す。量、充足状態、品質、基準比較を1つのbooleanへ潰さない。

既存の `eligible_for_reference`、`eligible_days`、`average_known_amount`、`percent_energy`、従来の `dri` は完全データ日の旧意味を維持する。互換フィールドを「部分データ込みの総量」へ転用しない。新UIと見直し理由は新evidenceを明示的に使用する。過去のPhase 6設計にある「完全日のみで比較」の規定は、この新evidence経路について本設計へ置き換える。旧経路の説明としては残る。

## 品質と推定の未解決事項

現RPCは欠損があれば日別qualityを `unknown_or_incomplete` とするため、既知分だけの品質を返さない。元のスナップショットに `provenance` があっても、日別集計から推定量や推定由来を分離できない。`user_verified` もユーザーが確認した属性であり、分析値・実測値・誤差なしを意味しない。

したがって、新モデルの `quality:unknown` を「欠損部分以外は確定値」と読み替えない。`estimate_status:not_resolved` を保ち、参考比較は登録値を前提とすることを説明する。`imputation:none` を画面で「推定なし」と表示しない。由来の確認は栄養素→日→食事→食品の既存詳細から行う。完全な日でも未確認値・既存推定があり得るため、`basis:complete` と品質表示を切り離さない。

将来Cを導入するには、栄養素単位の出典、参照食品、調理状態、成分定義、単位、補完方法、品質、元値、改訂を保持し、確定値・推定値・未知を区別する必要がある。点推定は真値を上回り得るため、推定小計を無条件に生物学的下限へ加えてはならない。有限の不確実性範囲を導入する場合も、その根拠と適用条件を別途設計する。

## 比較アルゴリズム

### 直接量

非負で有限の登録値を小計する。対象集合の全食品について値があれば `lower = upper`。欠損があれば `upper = null` とし、根拠のない最大値は作らない。非有限・負の集計値があれば比較を保留する。

| 指標 | 部分データから成立する事実 | 保留する判断 |
|---|---|---|
| EAR / RDA | 下限がRDA以上なら「登録された既知分だけでRDA以上」 | 下限がEAR/RDA未満であることから、総量の不足やEAR未満を結論しない |
| AI | 下限がAI以上なら「既知分だけでAI以上」 | AI未満で不足と判断しない。完全データでも同じ |
| DG 下限だけ | 下限が境界を満たすなら下限到達を確認できる | 下限未到達から総量未到達を結論しない |
| DG 上限だけ | 下限が上限を逸脱すれば、既知分でも逸脱 | 上限不明の範囲から上限以内を結論しない |
| DG 両側 | 範囲全体が一方へ逸脱する場合の方向だけ | 一部しか範囲内でないときの「範囲内」 |
| UL | 比較可能な下限がULを超えれば、既知分でも超過 | 有限上限なしでの「UL以下」「安全」 |
| EER_REFERENCE | 参考値の提示 | 単純な大小によるエネルギー不足・過剰の診断 |

DG の包含・非包含境界とULの比較演算は既存定義を維持する。部分データでRDA到達が分かっても、ULやDGが問題ないと判断した意味にはしない。同じ栄養素の独立した軸を別々に表示する。

ULは既存resolverの `comparable` と `comparisonScope` を維持する。例えばビタミンAのULはプロビタミンAカロテノイドを含む総量との単純比較には使えず、葉酸の通常食品由来folateとサプリメント等由来folic acidも比較対象が異なる。部分データ対応を理由に比較不能な基準を有効化しない。[MHLW 脂溶性ビタミン、冊子p.154](https://www.mhlw.go.jp/content/10904750/001316466.pdf)、[MHLW 水溶性ビタミン、冊子p.208](https://www.mhlw.go.jp/content/10904750/001316467.pdf)

### エネルギー比

比率は同じ日集合の `100 × 栄養素g合計 × 換算係数 / エネルギー合計` とする。脂質は9、たんぱく質・炭水化物は4を既存定義どおり使う。日別パーセントの単純平均や、栄養素とエネルギーを異なる日集合で平均して割る方法には変更しない。gでの目標と%EのDGは別指標として表示する。DGの対象は総エネルギー摂取量に占める割合である。[MHLW エネルギー産生栄養素バランス](https://www.mhlw.go.jp/content/10904750/001316465.pdf)

栄養素の非負量をN、エネルギーをE、係数をcとする。使えるエネルギー下限が正であることを条件とする。

| 分子N | 分母E | 比率の範囲 |
|---|---|---|
| 完全 | 完全 | 単一値 `100cN/E` |
| 部分 | 完全 | `[100cL_N/E, 上限不明]` |
| 完全 | 部分 | `[0, 100cN/L_E]` |
| 部分 | 部分 | `[0, 上限不明]`。既知小計同士の比は下限でも上限でもない |
| 情報なし、またはEの小計が0以下 | 任意 | 比較保留 |

分子完全・分母部分の0は比率範囲の算術下端であり「脂質比率0%」の点推定ではない。上下端からDGの片方向逸脱が成立するときだけ事実を返す。両方部分の既知量同士の割合を「現在の脂質比率」として表示しない。

### 基準が期間内で変わる場合

年齢区分等で期間内の基準が変わる場合は、既存の `stableReferences` を evidence の日付集合にも適用する。変わった指標だけ期間比較を保留する。完全日だけで安定性を確認して、部分日へその結果を広げない。

## 表示と見直し提案

主表示は、(1)既知の量、(2)基準との比較、(3)参考・保留とデータ状態、(4)次に確認する内容の順にする。内訳で完全/部分/全不明/未完了の件数、未知値のある食品、出典と品質を確認できるようにする。

下表の値はすべて設計説明用の合成例であり、ユーザーの食品・食事・摂取量の転記ではない。閾値も例として固定している。

| 合成ケース | 従来の表示・比較 | 新しい表示・比較 |
|---|---|---|
| 記録完了7日すべてビタミンC部分データ、各日既知125mg、例示RDA100mg | 既知分平均125mgはあるが、完全日0で基準比較なし | 「記録日平均の下限125mg以上」「完全0日・部分7日」「登録された既知分だけでRDA以上（参考）」 |
| 同じ7日で各日既知35mg | 完全日0で基準比較なし | 「下限35mg以上」「判定保留：未判明分があるため不足とは判断できません」 |
| 栄養素が7日すべて全不明 | 観察量なし | 「量は不明」「全不明7日」。0mgとは表示しない |
| 脂質の分子は部分、既知55g、エネルギーは完全1500kcal、例示DG20–30%E | 脂質の完全日だけへ対象が限定される | 「脂質55g以上」「脂質エネルギー比33%以上」「既知分でもDG上限超過（参考）」 |
| 脂質とエネルギーがともに部分 | 相互に完全な日だけ比較、なければ対象0日 | 既知gは表示し、「エネルギーも一部不明のため比率の判定は保留」 |

`4/7日` のような単独ラベルを使う場合は、分子・分母の説明を必須とする。新表示では「記録完了7日／栄養値完全0日・部分7日」のように意味を添える。値が観察日だけの平均なら「判明した日の既知分平均」、全記録日集合の下限なら「記録日平均の下限」として区別する。

部分データの低い既知小計から「次の食事で不足を補う」と誘導しない。その場合の次の行動は、内訳で未判明値や記録の抜けを確認すること。登録量を前提として成立する到達・上限逸脱等は参考事実として示すが、データ充足率を健康スコアに変換しない。エネルギーもEERとの差だけで診断せず、体重変化等の文脈を要する。[MHLW エネルギー必要量](https://www.mhlw.go.jp/content/10904750/001564948.pdf)

## 長期評価と残存する限界

### 基準の位置と表示の優先度を分離する

EAR・RDA・AI・DG・ULの数値や比較結果は変更しない。一律の許容率や仮の補完値によって「到達」に変換しない。EAR以上RDA未満の平均は `ear_to_rda` を維持し、強い見直しの `review` から `watch`（参考・経過を見る）へ移す。比較可能なUL超過、EAR未満、DG範囲外を先に示し、情報不足の保留は別の欄に分ける。既存の互換経路にも同じ表示優先度を適用する。

栄養値が完全にそろう期間で、平均がEAR以上RDA未満なら「推奨量との差」を同じ単位で表示する。この差は基準値と観察平均の算術差であり、個人の不足量や追加摂取の必要量ではない。部分データで低い下限しかない場合は、不明分を考慮できないため差を表示せず保留を維持する。推奨量との差だけを理由に、食事記録の不足や緊急の食生活改善を案内しない。

参考のRDA差と強いDG逸脱が同じ栄養素にある場合、参考の増量方向を理由に強い逸脱の方向を `mixed` へ変えない。EAR未満とDG上限超過など、見直し対象となる根拠が実際に相反する場合は `mixed` を維持する。

共通の記録日集合を使うことで栄養値欠損に由来する選択を減らすが、食事を記録した日そのものの偏りは解消しない。7/30/90日は観察窓であり、選択した暦日の通常摂取量を推定しきった意味にはしない。週末、季節、外食、サプリメント摂取等の偏りや日間変動が残り、90日を選んだだけで確実になるわけではない。

`complete_days=0` でも部分日の既知情報を確認でき、基準に対して一方向の比較が成立する場合は参考事実を示せることが改善点である。有効な比較がない栄養素は保留を残す。保留を減らすための根拠のない推定、0補完、完全日数の水増しは行わない。

## 検証要件

Vitest等の合成fixtureで次の性質を回帰検証する。

1. 全食品判明、一部欠損、全不明、明示0を区別する。
2. 食事記録の完了・未完了・空の完了を区別し、未記録を0にしない。
3. 完全日0・毎日部分のビタミンでも既知量を表示でき、RDA到達は参考事実、低い下限は保留になる。
4. AI未満を不足にせず、比較可能なUL既知分超過を示し、比較不能ULを使わない。
5. DGの上下限と包含境界を維持し、片側だけの根拠から「範囲内」を作らない。
6. 分子・分母の完全/部分の組合せ、正でないエネルギー、同じ日集合による期間比率を検証する。
7. `estimate_status:not_resolved`、`imputation:none`、qualityとcoverageの独立性を保持する。
8. 7/30/90日、全不明日を含む共通分母、観察日平均との相違、基準の期間内変更を検証する。
9. 同じ入力で同じ結果となり、合成入力の明示的修正後も小計・日数・範囲が整合する。
10. 旧complete-onlyフィールドの意味を維持する。

SQL検証では認証必須、owner絞り込み、RLS、`security invoker`、日付範囲の上限を維持する。取得側はAPIの行数上限を考慮して期間を分割し、各日×各栄養素の組が全件あることを検証する。途中で切れた応答から正常な90日平均を作らず失敗させる。

lint / typecheck / test / build の結果とPreviewの確認範囲は実行結果として別途報告する。テストを記述しただけで本番実測やPreview確認が済んだとはしない。

## 保存値、セキュリティ、Production反映

集計は既存の摂取時スナップショットから導出する。カタログ栄養値の変更だけで過去の記録が自動修正されたと扱わない。既存の明示的な食事編集・再スナップショット等の操作が行われた場合のみ、更新後の記録に従って再集計する。今回の欠損対応では既存記録、出典、qualityを書き換えない。

本設計は既存RPCの列からTypeScriptで導出できるため、この変更だけを理由とするDB migrationは不要。将来、既知分品質や推定由来をRPCへ追加する場合は、Auth/RLSを維持したmigrationとして管理する。新たな有料APIや外部サービスへの依存は追加しない。

作業ブランチとProductionに影響しないPreviewで検証する。**Production deploy、Production migration、Production DB更新は、それぞれ実行内容を提示して明示承認を得るまで実行しない。** PR作成やPreviewの成功をProduction反映の承認と解釈しない。本番調査はread-onlyかつ集計情報だけとし、食品名、日付、ユーザー識別子、秘密情報をログや公開PRへ出さない。
