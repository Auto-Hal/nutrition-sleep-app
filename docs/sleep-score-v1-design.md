# 睡眠スコア v1 と改善提案の設計

設計日: 2026-10-26。対象: 睡眠ページ、Today、既存の睡眠ガイド。

## 決定と適用範囲

**主な夜間睡眠時間 50点、起床時刻の規則性 30点、計測上の睡眠効率 20点を合計する。** これは行動の振り返りのために本アプリが定める `Sleep Score v1` であり、医学的に検証された評価尺度、睡眠の良し悪しの診断、睡眠障害の検出には使わない。

指定された配点を変更する十分な根拠はないため、v1 の製品仮説として採用する。時間を最も重くし、生活のリズムを次に置き、機器の覚醒推定に左右される効率は20点に抑える。配点や補間曲線の医学的優越性を主張しない。将来変更するときはバージョンを変更し、異なるモデルの総合点をそのまま比較しない。

成人向けの参考モデルである。既知の年齢が18歳未満なら総合スコアを算出せず、元の睡眠記録を表示する。年齢未登録では成人向け参考モデルと明示する。65歳以上に成人共通の曲線を適用することには限界があり、年齢、眠気、休養感に応じた必要量が異なる旨を表示する。個別の必要睡眠量や交替制勤務を推定する機能ではない。新たな日次入力は求めない。

## 科学的根拠と製品判断の区別

厚生労働省の成人向けガイドは6時間以上を目安とし、個人差と睡眠休養感を重視する。AASM/SRS の声明は18〜60歳を主な対象として継続的な7時間以上を推奨し、9時間超が適切な場合も認めている。したがって「6時間」と「7時間」は同じ意味の合格線にせず、長いという理由だけで減点しない。[MHLW 睡眠ガイド2023、成人版](https://www.mhlw.go.jp/content/001305530.pdf)、[AASM/SRS 2015 原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC4442216/)、[AASM 公開PDF](https://www.aasm.org/resources/pdf/adultsleepdurationconsensus.pdf)

AASM の消費者向け睡眠技術に関する声明は、機器の情報を医療評価の代替にしないよう求める。PSG と7機器を比較した研究ではステージ分類の性能は機器間で一定せず、家庭での4機器研究でもステージ推定のばらつきが報告されている。v1 は睡眠ステージを採点せず、時間・効率も機器による推定として扱う。[AASM 2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC5940440/)、[Chinoy et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8120339/)、[Chinoy et al. 2022](https://pubmed.ncbi.nlm.nih.gov/35345630/)

以下の全配点、区分間の補間、15/45/90/120分、効率60/75/85/90%、履歴3夜、期間比較の件数・充足率は**公的基準ではなく本アプリの表示と行動提案のための閾値**である。研究からこれらの数値の有効性や疾患リスクを導いたものではない。

## 既存実装の課題

- `lib/sleep/analytics.ts` は日別の全セッションの合計、主な睡眠、昼寝、ステージ等を区別している。一方、従来の睡眠時間の完全性は昼寝を含む当日の全セッションに依存する。
- 従来の `sleepGuide()` は最新の完全な日が集計終了日と一致せず、または完全な日が3日未満だと記録確認へ戻る。朝の同期待ちや昼寝だけの欠損で、過去に有効な夜間記録があっても助言が消える。
- 起床時刻の通常の算術平均・標準偏差は、00時をまたぐデータを適切に比較できない。
- 日別の時間・効率等の数値だけでは、どの項目を見直すか、期間差のどの項目が変わったかが分かりにくい。
- `sleep-repository.ts` は Provider のペイロード変更を upsert し、対象期間で消えたレコードを `superseded_at` によって除外する。同期済みの値は不変ではない。

既存の合計睡眠時間、昼寝、ステージ、詳細タイムラインと同期設定は残し、スコアの入力・分母は別に定義する。

## 入力とセッションの選択

正本は既存の `sleep_sessions` と関連区間である。スコア専用テーブル、AI API、有料サービスは追加しない。ユーザー認証を経た既存の取得経路で読み、現在の正本から毎回決定論的に計算する。

1. `superseded_at` があるレコードを除く。
2. 日付は既存の `sleep_date` を使い、表示終了日より未来の記録は集計しない。
3. Provider が昼寝と明示したセッションを主な睡眠に選ばない。複数候補では既存の主睡眠選択と整合する決定論的な規則を使う。
4. 選ばれた主な睡眠の `minutes_asleep`、`time_in_bed_minutes`、起床時刻を使う。昼寝の値や他セッションの分母と混ぜない。
5. 主な睡眠が Provider 処理中ならスコアも処理中にする。主な睡眠が有効なら、別の昼寝が処理中であることだけで採点を止めない。
6. STAGES、CLASSIC、詳細ステージなしの形式に同じ算出式を使う。ステージの欠損や重複だけで有効な時間・効率を消さない。

現Google Healthの`time_in_bed_minutes`には`minutesInSleepPeriod`（提供元が定める就寝から起床までの睡眠区間、全ステージ合計）を保存している。実際の寝床滞在を別に実測した値ではないため、画面では「提供元の睡眠区間」を分母とする計測上の効率と説明する。医療評価の睡眠効率と同一視しない。[Google Health公式フィールド定義](https://developers.google.com/health/reference/rest/v4/users.dataTypes.dataPoints#SleepSummary)

主な睡眠が選べない昼寝のみの記録では、その理由を示して総合スコアを保留する。主な睡眠の候補選択自体が機器の分類に依存し、交替制勤務等を完全に表せない限界は残る。

## 算出式

各素点は0〜100。節点 `(x0,y0)` と `(x1,y1)` の間は `y0 + (x-x0)/(x1-x0) × (y1-y0)` とし、範囲外は下記の端点の扱いに従う。各項目の獲得点は `素点 × 配点 / 100`。合計前に項目を整数へ丸めず、通常総合点は合計後に四捨五入した整数を表示する。内訳や暫定範囲は丸め前の値から表示するため、表示桁による小差を正確な点数差と解釈しない。

### 主な夜間睡眠時間: 50点

入力は `minutes_asleep`。有限の非負値であり、セッションの経過時間等と矛盾しないことを確認する。0分の明示値と NULL を分ける。NULL や矛盾した主要値から総合点は作らない。

| 主な夜間睡眠 | 素点 | 獲得点 |
|---|---:|---:|
| 240分以下 | 0 | 0 |
| 300分 | 35 | 17.5 |
| 360分 | 65 | 32.5 |
| 420分以上 | 100 | 50 |

420〜540分は満点を維持し、540分超も長さだけで減点しない。必要なら長い睡眠の観測傾向を別に示すが、病気や過剰睡眠とは判定しない。昼寝は別表示し、夜間時間へ足して採点しない。

### 起床時刻の規則性: 30点

対象日の前14暦日以内から比較可能な主な睡眠を直近7夜まで選び、最低3夜必要とする。対象日自身と未来の記録は基準へ含めない。表示開始日前の記録は基準計算だけに使い、表示日数や平均の分母に含めない。

時刻は1日1440分の円環として扱い、2時刻の差を `min(abs(a-b), 1440-abs(a-b))` とする。基準には最短弧距離の総和を最小化する円環中央値（観測候補に基づく medoid）を使う。算術平均と比べ日付跨ぎを扱え、単発の外れ値の影響も抑えやすい。同点なら最新の観測日を優先し、同じ入力から常に同じ基準を得る。基準候補から180分以内に過半数の夜がなければ、基準が曖昧として規則性を未評価にする。この180分も製品上の防御条件である。

| 基準起床時刻からの最短差 | 素点 | 獲得点 |
|---|---:|---:|
| 15分以内 | 100 | 30 |
| 45分 | 80 | 24 |
| 90分 | 30 | 9 |
| 120分以上 | 0 | 0 |

起床時刻は保存された現地 UTC offset を優先する。不明の場合はプロフィールのタイムゾーンを使い、`clock_timezone_fallback` として参考計算の理由を保持する。規則性の基準には対象夜の起床時と同じ offset で、かつ保存 offset 同士または fallback 同士の履歴だけを使う。旅行や DST による offset 変更の直後に比較可能夜が足りなければ、規則性だけ未評価にする。保存 offset とプロフィールから推定した offset を同一条件として混在させない。UTC 経過時間による時間・効率の計算と、現地の時計による規則性を分ける。offset だけでは旅行と DST、地域そのものは識別できず、fallback では当時の旅行による現地時刻を再現できない場合がある。

例として23:50と00:10の時計差は20分であり、23時間40分ではない。主な夜間睡眠の終了が深夜であっても、時計差の計算方法を変えない。

### 計測上の睡眠効率: 20点

同じ主な睡眠の `minutes_asleep / time_in_bed_minutes × 100` を使う。提供元の別の定義を持つ `efficiency` フィールドへ暗黙に切り替えない。

| 効率 | 素点 | 獲得点 |
|---|---:|---:|
| 60%以下 | 0 | 0 |
| 75% | 50 | 10 |
| 85% | 85 | 17 |
| 90%以上 | 100 | 20 |

分母は正であり、分子・分母は有限の非負値、分子は分母以下である必要がある。NULL、0分母、100%を超える比、経過時間との矛盾では効率項目を未評価にする。機器のステージに欠損があるという理由だけでは、この独立した有効な比率を消さない。「計測上」と表示し、臨床検査による睡眠効率と同一視しない。

## 成立条件と欠損

状態とスコアの良し悪しは独立させる。

| 状態 | 条件 | 表示と集計 |
|---|---|---|
| 通常スコア | 主な睡眠が処理中と明示されておらず、時間・規則性・効率がすべて評価可能 | 合計 `/100点`。通常平均へ利用 |
| 暫定スコア | 有効な主睡眠時間があり、一部の副指標だけ未評価 | 獲得点 `/評価可能な配点`、カバー率、総合点の取り得る範囲を併記。通常平均から除外 |
| 算出保留 | 主要な睡眠時間が不明・矛盾、主睡眠を選べない、年齢による対象外等 | 個別の観測値と理由を表示。点数にしない |
| 未観測 | 対象日の睡眠記録がない | 未観測。0点にしない |
| 処理中 | 主な睡眠の Provider 処理が未完了 | 処理中。確定したスコアとして比較しない |

暫定のカバー率は `評価可能な配点 / 100` で、観測の正確さや医学的信頼度の確率ではない。暫定総合範囲は `[獲得点, 獲得点 + 未評価配点]`。欠けた配点を0と決めたり、獲得点を利用可能配点で割って100点へ正規化したりしない。この範囲は欠測項目の数理的な取り得る範囲であり、統計的な信頼区間ではない。

Provider の処理完了フラグが NULL の旧記録は、NULL を未処理 false に置き換えない。元の数値が成立する場合は採点できるが、処理完了が未確認という理由を保持する。通常という状態は3項目の算出成立を表し、Provider による精度の保証を表さない。

架空例: 7時間30分、計測効率93.75%、規則性の履歴なしなら `70/70点を確認・カバー率70%・総合70〜100点`。100点と表示して通常点と混ぜない。同じ時間・効率で規則性も満点なら通常100点。主要時間が NULL なら効率や規則性だけで総合点を作らない。

各項目には、配点、観測値、比較基準、獲得点または未評価理由、見直せる行動を保持する。内部では丸め前の値を保持し、画面の丸めと計算のバージョンを統一する。

## 7日・30日・90日の傾向

表示期間と前期間は同じ長さで連続し、重複させない。基準計算のため前期間開始日からさらに14日を読む。現在日以降の未来データを混ぜない。期間外の履歴は基準計算専用である。

通常スコアだけの平均、暫定・保留・未観測・処理中の各件数を分ける。時間・効率・時計時刻の表示にも各指標の利用日数を持たせる。表示対象の暦日数を記録件数へすり替えない。

期間平均値の観測件数と、「傾向や前期間差を説明してよいか」を別に扱う。前期間との増減説明には、両期間とも同じ v1、同じ3項目での通常スコアであること、下表の通常件数と50%以上の充足率を必要とする。これは断片的な記録から強い結論を出さないための製品条件で、代表性を保証しない。

| 期間 | 通常スコアの最低件数 | さらに必要な条件 |
|---|---:|---|
| 7日 | 3夜 | 各期間で暦日数の50%以上が通常スコア |
| 30日 | 7夜 | 同上 |
| 90日 | 14夜 | 同上 |

比較成立時の項目寄与は、通常スコアに採用した同じ夜集合で各項目の平均を取り、現在期間と前期間の差を求める。最も差に寄与した項目を説明できるが、「睡眠時間が原因で健康が改善した」のような因果関係にはしない。「観測できた通常スコア平均が○点変化。内訳では睡眠時間項目の変化が最大」とする。充足率や観測夜の違いは残るため、生活全体の確実な改善・悪化とは表現しない。

睡眠時間の推移、起床・就寝の時計時刻の散らばり、計測効率を総合点と別に表示する。グラフでは未観測、保留、処理中を0へ結ばない。暫定点は通常点と異なる形とラベルで示し、同じ100点時系列の通常点として線でつながない。

## 改善提案

自由生成 AI を使わず、観測値と固定ルールから選ぶ。各提案は課題、根拠値、期間、利用夜数・確実性の制約、行動、期待する方向、詳細リンクを保持する。画面には最優先1件、詳細に次の候補を表示する。

優先順位は、継続的な極端な短時間、継続的な短時間、起床の変動、継続的な低効率、週末と平日の時刻・時間差、維持、記録確認とする。単発の短時間・低点から継続的な問題と断定しない。必要件数を満たさない指標は生活改善の強い評価に使わず、利用できる観測値は残す。具体的な採用条件は実装の設定・テストで固定する。

| 観測に応じた課題 | 行動の方向 |
|---|---|
| 主な夜間睡眠が継続的に短い | 就寝準備を20〜30分早められるか試す。眠れないまま長時間寝床にいることを目的にしない |
| 起床の時計時刻が大きく変動 | 生活に合う起床時刻の目安を決める |
| 計測上の効率が継続的に低い | 寝室の光・音・温度、就寝前の過ごし方を見直す。病名を推定しない |
| 土日と平日の睡眠時間・起床が異なる | 時間差と時計時刻差を別々に説明し、平日の睡眠確保を検討する。土日をその人の休日と断定しない |
| 比較的安定 | 現在の時間と生活リズムを続けて確認する。新たな問題を作らない |
| 不十分な記録・同期異常 | 接続、最終同期、処理状態を確認する。睡眠不足と呼ばない |

当日が未観測でも、直近の有効な観測期間から得られる提案は記録日を付けて維持する。同期待ち・認証異常等の通知は生活評価と別に表示し、朝に未観測なことだけで睡眠悪化や提案の消失を起こさない。古い観測しかないときは古さを示し、現在の状態を断定しない。

症状が続く、強い日中の眠気がある、いびきや無呼吸を指摘された等の場合は、点数と関係なく専門家へ相談する一般情報を詳細に用意する。単発の低スコアを危険と呼ばず、高い点数で症状を否定しない。

## 画面構成

睡眠ページは、最新の観測日付きスコア、最優先の提案、7/30/90日切替と推移、採点内訳、元の指標と日別タイムライン、履歴、Google Health の接続・同期設定の順を基本にする。最新の観測日が当日なら昨夜の記録として示し、古ければ日付を明示する。

通常点は100点満点を視覚的にも示す。暫定は評価可能配点と未評価範囲を中心に示し、通常点に見える満点ゲージへ変換しない。色だけで状態を伝えず、文字、点の形、数値と単位を併用する。グラフには読み上げ可能な説明と数値の確認手段を用意する。

Today は最新スコア、主な夜間睡眠時間、短い提案、詳細へのリンクに絞る。栄養登録・栄養要約の導線を維持する。詳しい閾値や内訳は展開可能にする。iPhone の縦画面を優先し、iPad の幅でも自然な余白と列数にする。

## 実装・再計算・セキュリティ

スコア設定、純粋な計算、傾向と提案、UI を分離し、`analytics.ts` は取得と既存集計の責務を保つ。Provider のデータ修正後は現行レコードを再読込して過去のスコア、過去の起床基準、それに依存する後続夜、期間平均と提案を再計算する。スコア永続化や独自キャッシュによる古い値の残存を避ける。

既存の認証、RLS、ページング、所有者での取得を維持する。秘密・アクセストークン・実ユーザーの睡眠値をログ、公開PR、テストfixtureへ出さない。追加データ取得は現在期間、同長の前期間、基準用14日に限定し、通常の期間表示の分母へ読み足した日を入れない。DB migration はこの派生評価だけでは不要である。

同期処理は Provider の権威的な更新ウィンドウ内で既存の冪等 upsert/差替え/失効処理を使う。スコア追加のために過去睡眠履歴を破壊せず、接続・再認証・同期エラーの導線も維持する。

## 検証と受け入れ

単体テストは補間の全節点、丸め、0/NULL/矛盾、正常・暫定・保留・未観測・処理中、昼寝、複数候補、ステージなし・重複、円環時刻、offset/DST、履歴不足、未来除外、7/30/90日、通常のみの比較、訂正後の再計算、提案順位を架空データで確認する。既存の栄養・Today・Settings・認証・同期テストも実行する。

`lint / typecheck / test / build` と CI、利用可能な Playwright E2E、Preview で画面・期間切替・グラフ・採点内訳を検証する。自動ブラウザの iPhone/iPad 相当表示は実機 Safari の代替と扱わない。機器を使う Google Health 同期、再認証、PWA の起動・更新、Safari 固有の表示は、実機操作で未確認なら未確認と報告する。

実機受け入れの最小手順:

1. iPhone Safari と iPad Safari で Preview にログインし、Today と睡眠ページを開く。横スクロールや文字切れがないことを確認する。
2. 7/30/90日を切り替え、最新の日付、通常/暫定/未観測等の件数、グラフ、内訳が一致することを確認する。
3. 1夜の内訳で同一の主な睡眠の時間と効率を確認し、表示される点数が説明と一致することを確認する。
4. 既存の接続・同期操作で最新記録を更新し、処理中/同期待ちを不良スコアと表示しないことを確認する。必要時の再認証や同期エラーの案内が残ることを確認する。
5. ホーム画面へ追加済みの場合は PWA を再表示・更新し、最新版の Today/睡眠ページと栄養登録が使えることを確認する。

実装済み、CI 成功、Preview 自動検証、実機承認を区別してリリース報告へ残す。実行できなかった項目を PASS にしない。

## Production ゲートとロールバック

このタスクの Production 変更には、今回の変更内容に対する明示的な最終承認が必要であり、以前の栄養機能の反映承認を流用しない。実装、レビュー、CI、Preview、セキュリティ、実機受け入れの結果を揃え、未確認があれば解消してから Production GO を求める。承認前に main へマージ、Production deploy、Production DB 変更をしない。

GO 後は検証した PR head を main へマージし、その確定 SHA を Production へデプロイする。配信バージョン、認証、本人の記録に対するスコア・内訳・期間集計・提案・Today、同期、栄養の回帰を確認し、実データを公開出力しない。

派生評価のみで DB を変えないため、問題時は直前の既知正常 Production deployment へ戻し、必要に応じて PR を revert する。睡眠の正本データを削除・巻き戻す必要はない。デプロイの切替えとコードの revert は別作業として記録する。

## 残る限界と v2 の条件

- 機器、装着状態、処理更新による測定誤差は点数化しても消えない。段階なしでも使える一方、機器差の校正はない。
- 完全な通常点だけの期間比較も、欠測が偏ると実際の生活を代表しない。件数・分母を見せても代表性の証明にはならない。
- 睡眠休養感、日中の眠気、交替勤務、個別の必要時間を直接評価していない。高得点は健康や十分な休養を保証しない。
- 土日/平日は暦の分類であり、その人の休日ではない。旅行/DSTと地域の違いは保存offsetだけでは識別できない。
- 長時間睡眠、ステージ比率、疾患の予測は v1 の採点対象外。v2 で扱う場合は対象集団、機器差、妥当性検証、再計算とバージョン比較の方法を先に定める。
