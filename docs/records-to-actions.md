# 記録を次の行動につなげるUI改修

## 目的と制約

食事・睡眠の記録から、確認できる状態、見直す要因、次にすることをつなげる。体調・疲労・眠気の追加入力は求めない。記録だけで身体の状態や不調の原因を確定できるとは扱わず、総合健康スコアや因果関係の推定値を作らない。

| 画面 | 目的 | 記録後の行動 |
| --- | --- | --- |
| 今日 | 食事を登録し、当日の記録を確認する | 登録 → 集計・食事一覧・未同期状態の確認 |
| 栄養 | 各栄養素の期間平均と摂取源を確認する | 7日平均（30・90日も選択可） → 栄養素 → 日別・食品別の摂取源 → 次の献立 |
| 睡眠 | 時間・リズムと眠りの経過を確認する | 期間平均 → 主な睡眠・昼寝の詳細 → 今夜の過ごし方 → 同じ条件で比較 |
| 設定 | プロフィール、連携、データを管理する | 判断に必要な設定や元データを整える |

Todayは登録と当日の記録に絞り、栄養素の不足・改善ガイドを表示しない。栄養画面は全栄養素の期間平均を先に表示する。分析画面で目的、観測事実、根拠と対象日数、次にすること、改善手順を示す。記録が足りない場合は、確認・補完・同期を先に案内する。

## この変更で実装したもの

- 日本語ナビゲーション、主要画面の目的説明、共通の行動ガイド、スマートフォンでの読みやすさ・フォーカス表示。
- Todayの分析カード・重複した睡眠導線・専用ガイド取得APIを削除。食事登録、確認待ち（ある場合のみ）、当日のエネルギー集計、食事一覧と同期状態を表示。期間分析には「7日平均を見る」から進む。
- 栄養は全18栄養素の既知分平均、既知・評価日数、既存の食品・サプリ・日別内訳を維持。7日を初期表示にし、30・90日も選択できる。既存DRI評価の根拠日数と品質を引き継ぐ。優先項目がある場合はその摂取源へつなぐ。未確認値を含む場合には確認が先であることを示す。
- 睡眠は完全な時間データだけを扱う。直近日が未観測、比較に必要な記録が3日未満、または接続に問題がある場合は記録確認を案内する。最近の完全記録に対する時間差・起床時刻のばらつきは、見直す表示順に使う。
- 改善手順は「根拠を確認 → 1つ見直す → 次の7日間も同じ基準で比較」。行動の実施・達成を保存する機能や、改善効果の因果判定を実装したものではない。

睡眠ガイドの「以前の平均より60分以上短い」「起床時刻の標準偏差60分以上」は、表示候補を選ぶ暫定的なUIルールであり、医学的な異常値や最適睡眠時間の基準ではない。昼寝を含む日合計を「昨夜の睡眠」とは呼ばず、日付と合計で表示する。

基準値評価と記録の既知分は同じものではない。食事摂取基準は習慣的な摂取の評価に使い、日中の記録途中から不足と判断しない。[厚生労働省の説明](https://kennet.mhlw.go.jp/information/information/dictionary/food/ye-025)

睡眠の改善は時間だけではなく休養感や個人差も関わる。今回の入力条件では休養感を測定しないため、睡眠時間・リズムの記録の整理に表示の範囲を限る。[厚生労働省の睡眠対策](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/kenkou/suimin/index.html)

## 優先修正との対応

| レビューID | 今回の対応 |
| --- | --- |
| R01 | 最新集計の採用と同期完了の照合を分離。連続登録・集計失敗後の再取得・遅延したoutbox復元で暫定値を残さない |
| R02 | 食事・欠食の未同期状態とイベントを対象日で絞る。取消は対象食事IDで絞る |
| R08 | 食事一覧もマウント・画面復帰時に再取得。古い応答で最新の一覧を上書きしない |
| R03 | datetime-localに端末のローカル時刻を設定。過去日入力は選択した日付を使用。プロフィールと端末の時差が異なる場合の統一は残課題 |
| R04 | 同じ編集画面の再試行では操作ID・作成時刻・送信内容を固定。成功結果の照会で復帰。結果不明時は編集をロック。画面を閉じた後まで操作を永続化する機能は未追加 |
| R07 | 栄養は最大28日ごとの取得と全日・全栄養素の検査。睡眠はセッション・ステージ・離床を正確な件数と安定した順序でページ取得。不完全な取得結果から集計しない |

## 次の優先項目

1. R06：摂取源の食品／サプリ分類と、商品同定の信頼性を別に保持する。ChatGPT登録のサプリを正しく内訳に含める。保存済みの不変スナップショットとの互換性を設計する。
2. R05：食品／サプリ別の既知・不明件数を返し、記録平均の内訳・品質の対象日をそろえる。
3. カタログ・fingerprint一覧など、R07に含まれる残りの一括取得をページ取得へ移す。
4. 食事のお気に入り・前回と同じ、再利用したいLibraryと履歴用項目の整理。必要に応じ、心拍変動・呼吸数などを既存の睡眠記録と対応づける設計。
5. 行動を選んだ日・期間・対象を管理し、変更前後を並べる仕組み。食事・睡眠だけで確認できる変化を表示し、実施の有無や効果を推測で確定しない。
6. README・ロードマップ・Node指定・本番マイグレーション台帳とデプロイ環境の整合。

## 睡眠詳細と導入順

Google Healthの[睡眠ガイド](https://developers.google.com/health/data-types/sleep)と[正規REST仕様](https://developers.google.com/health/reference/rest/v4/users.dataTypes.dataPoints#Sleep)を確認した。既存のsleep読み取り権限を使用する。

- 保存済みの入眠時間、起床後の時間、覚醒時間、処理状態、手動編集情報を平均・詳細に使用する。平均ごとに評価日数を示す。入眠の0は自動検出で参考値となるため、手動編集が確認できない0を入眠平均から除外する。正の値は提供値として使用する。手動編集フラグは入床意図の完全な判別ではないため、平均も提供値の整理として扱う。
- 主な睡眠は昼寝を除いた最長のセッション。昼寝だけの日には就寝・起床の証拠を作らない。全日合計には昼寝を含むことを明記する。
- 1日のセッションを主な睡眠／昼寝／その他に分け、ステージの推移、時刻別一覧、途中の覚醒区間、短い覚醒・離床の記録を表示する。連続するAWAKEの分割を1区間にまとめ、端の覚醒を途中の回数に含めない。欠測・不明・重なりがある場合は覚醒回数を確定しない。
- CLASSICではLIGHT/DEEP/REMを0として補完しない。ステージ平均は観測分を対象にし、項目ごとの対象日数を表示する。空のステージが0となるのは、対応する種類の全区間が分かる場合だけ。処理中・重複した区間は平均から除外する。
- `shortAwakenings` はステージ・離床と独立に正規化し、`sleep_sessions.short_awakenings`（nullable JSONB配列）へ保存する。取得フィールド省略・既存未再同期はnull、明示的空配列は0区間。ステージと重なるため時間合計へ足さない。既存の所有者RLS、ブラウザーSELECTのみ、アカウント削除ガードを維持。明示的なデータエクスポートにも追加する。
- 既存のpayload hashにこのフィールドが含まれていた場合でも、`sleep_details_version`で一度だけ再正規化できるようにする。古い履歴を0区間とみなさない。

リリース時は **`20261010090000_sleep_details.sql`を先に適用し、その後アプリを更新する**。本作業では本番適用していない。通常の直近3日同期でその期間を補完できる。それより前の履歴は、必要な期間を再同期するまでは短い覚醒が情報なしとなる。提供元がこのフィールドを返さない記録も情報なしのまま。

呼吸数、HRV、SpO₂、皮膚温のような別データ種別は、体調の原因を確定する値として追加しない。次段階で利用する場合は、利用目的、対応するセッション、機器対応・欠測、読み取り権限を設計する。今回は時間・リズムと眠りの経過の分析に必要なsleep内の情報を使う。
