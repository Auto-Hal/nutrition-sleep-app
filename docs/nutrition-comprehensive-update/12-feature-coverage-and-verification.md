## 標準29項目の経路別対応

標準29と内部Naの合計30コード。旧18のコード・単位は変更していない。追加12は飽和脂肪酸、n3、n6、コレステロール、糖質、K、Mg、P、Cu、Se、Mo、葉酸。全項目を収録した食品DBを新規提供するという意味ではない。

| 経路 | 対応・検証の範囲 | 留意点 |
|---|---|---|
| Catalog手動登録/編集 | 30コード、由来/出典/定義、不明/0、明示計算 | Naは内部用の展開欄。既存未知metadataは変更しない限り保持 |
| Product手動/バーコード | 30コード、写真なし登録/編集、既存値の保全 | 実物の有効な番号を使用。番号なしはCatalog |
| 栄養表示OCR | 29項目の位置/行/単位回帰、ug/mg、RAE/DFE/IUの識別 | 実物撮影の認識率は未確認。不確かな形態を質量へ変換しない |
| 外部食品DB | 収録された定義一致の値を取り込む | OFFの総C/net C/糖類、generic A/E/葉酸を推測で統合しない。未知は未知 |
| Chat URL / draft / MCP / 直接登録 | 新v2の30コード・由来/定義、旧v1の18契約を併存 | 実ChatGPT OAuth/Projectでの成功は未確認。[利用指示](11-chat-v2-instructions.md)あり |
| Batch・作り置き | 30コード、材料量/食数、欠損と推定の伝播 | 一部材料が未知なら合計を既知の完全量にしない |
| Meal / MealEntry | 30コードの新snapshot、食事集計 | 旧18snapshotは18行のまま。新12を0やNULL行で追加しない |
| 日/7/30/90日/改善順位 | 全コードと品質/欠損、定義一致の既知量 | DRIの基準なし・比較不能と、摂取量が未知なことを区別 |
| JSON | v1の形を維持し、v2に新履歴・品質を追加 | v1にも定義/現在栄養行の新コードは含まれ得る。18限定enumの外部利用者には更新が必要 |

| 転送PNG | 基本7、全29の既知かつ定義一致の行 | 1対象1枚。未知/部分値は省略し通知。外部OCR成功とは別 |

## 数値・履歴・品質の契約

- プリセットは1800 kcal・25/20/55%、P112.5/F40.0/C247.5 g、fiber20 g、salt上限7.50 g、糖質参考227.5 g。本人指定の初期値であり、DRIや医学的最適値として扱わない。
- PFC比率100%を保存条件とする。gは4/9/4で有理数計算し、表示時だけ丸める。PFC構成比の分母はPFC由来エネルギー、記録energyは独立して維持する。
- 初期許容幅±10%の両端を含む。達成/不足側/超過側/保留/未記録/未同期を区別する。正式判定には当時の目標・完全記録・対象値の完全性・同期確認が必要。
- 記録途中もサーバーの既知量と暫定進捗を表示する。端末pendingの小計は別枠で、応答消失時の二重加算を避ける。古い食品参照は小計も保留する。
- 月間構成比は同じ対象日集合のPFCエネルギー合計から算出する。日別%の平均にしない。記録不足を栄養不足の日数へ入れない。
- 週間目標は各日の有効な目標を合算する。目標欠損時は完全週目標をNULLとし既知目標小計を別表示。未記録日を摂取0としない。
- 残りのE/F/Cは必要条件を満たすときだけ通常目標の0.9〜1.1倍内の参考量を表示する。条件外の数値を制限食の指示にせず、proteinの週末まとめ摂りを提案しない。
- 開始日前に正式目標は作らない。現在の目標での参考比較は本人のopt-inで別枠に表示し、版/日付/区分を示す。正式日数・週間残量には混入しない。
- 不明はNULL、確認された0と区別。微小正値がDB精度で0になる場合は新書込みをNULL＋理由にする。過去snapshotを再計算しない。
- Na→saltは2.54/1000。C−fiberは定義・資料・基準量が一致し本人確認した場合だけ。推定を計算しても公式値へ昇格させない。

## Body・転送・出力の実用上の制約

体重は1日1件。移動平均は7日内の実測だけを使い、n/7を示す。体脂肪の観測数は独立する。傾きは3点以上かつ14日以上の条件で参考表示。プロフィールの単一値から時系列を作らない。`profile_only`が初期値で、本人が`latest_measurement`へ切り替えた場合だけ最新実測をプロフィールへ反映する。最新の編集/削除と旧プロフィールAPIは共通lock/revisionで整合させ、最後の計測削除では連動体重をNULLにする。

PNGは白黒・高コントラスト、基本7は1200 px、全29は1440 px幅の1枚。画像は端末メモリだけに置き、Storage/outbox/SWへ保存しない。食事全体の既に倍率適用済みsnapshotを二重乗算しない。保存・共有・コピーは外部登録成功の検知ではなく、転送状態は本人が確認する。基本7の今回レイアウトでの再試験と全29のカロミル認識範囲は未確認。

CSVはUTF-8 BOM/CRLF、quote/改行・formula injection対策。DBの単一snapshotを全件検査して出力し、他ownerの値・認証情報を含めない。JSON v2は目標履歴・Body・転送履歴と栄養の品質情報を含む。アカウント削除は新テーブルも対象とする。
