# UI/UX構成案

対象はiPhoneの日常利用。緑・青の既存トークン、穏やかなsurface、数値と状態を併記する設計を継承する。以下は情報設計/wireframeで、コンポーネント実装や描画済み画面ではない。

## 1. 5タブと既存URL

| タブ | route | 主な責務 |
|---|---|---|
| 今日 | /today | 食事入力、当日energy/PFC、食事履歴、睡眠compact |
| 栄養 | /nutrition | PFC月間・週間・29項目とDRIの分析 |
| からだ | /body | 体重/体脂肪の記録・推移・目標 |
| 睡眠 | /sleep | 既存score、stage、傾向、提案、同期 |
| 設定 | /settings | profile、栄養目標、Library、export、account |

HistoryとLibraryは独立した主タブにせず、Todayの「履歴」「食品」から1tapで開ける。現在の/settings?view=library、/history、/history/edit、/nutrition-import、/today?date=は維持する。history/edit/importで今日タブをactiveにできるようroute判定を更新する。

Nutritionのサブタブは「PFC」「週間」「栄養詳細」の3つ。/nutritionの新しい初期表示はPFC。既存range/nutrient/day付きURLはview指定なしでも栄養詳細を開き、従来のdrilldownリンクを保つ。栄養詳細の7/30/90日計算・既存参照・見直し機能を残す。

## 2. Todayの最初の画面

390×844だけでなく360×740相当でも、日付、energy/PFC要約、主たる食事追加を最初のviewportに収めることを目標とする。Chat draftが多数ある日も要約の上へ長い一覧を挿入しない。ブラウザ文字拡大時は無理に固定高さへ押し込まず、読める自然なスクロールを許す。

    11月1日 今日            前日 / 履歴
    1800 kcal目標     記録 既知分 xxxx kcal
    P  xx.x /112.5g  差分 xx.xg  状態
    F  xx.x / 40.0g  差分 xx.xg  状態
    C  xx.x /247.5g  差分 xx.xg  状態
    食事 2/3枠確認済み ・ 未同期1件
    [食事を追加]  [ChatGPT]  [食品]
    朝食 / 昼食 / 夕食 / 間食・その他
    …日別食事履歴、各行の転送…
    最新観測日の睡眠scoreと提案 → 睡眠

目標g達成率は行の展開で確認可能。PFC構成比は「構成比を見る」で目標25/20/55と実際を対比し、4/9/4の定義を示す。構成比と目標g達成率を同じ棒や同じ%ラベルに載せない。

部分量には「既知分」「全量不明」、未同期には「端末に保存・未同期」。保存feedbackは既存optimistic方式を拡張し、同期済み表示はauthoritative再取得後だけ。未記録・欠損・通信失敗を0や赤い未達として表示しない。

目標未設定なら要約は記録量を残し、「目標を設定」からプリセット確認へ。体格参考値を既に選んだ個人目標として表示しない。

食事入力の選択・量・保存という現在の短い流れを維持する。29項目編集、goal設定、転送設定を通常の食事登録の必須ステップにしない。

## 3. Nutrition / PFC

上部に月選択、同じ日集合からの月間構成比、達成日数と分母、カレンダーを配置する。日別の%平均は使わない。

    [←] 2026年11月 [→]
    構成比 Pxx / Fxx / Cxx%  対象N日
    P N/M日  F N/M日  C N/M日
    全PFC N/M日  kcal N/M日  記録完了N日
    月 火 水 木 金 土 日
    [日付＋P/F/C状態の3印] × 月
    選択日 → P/F/Cの記録g・目標g・%・差分
    [この日の食事を見る] [転送]

7列の各cellは日付と3つの小さな状態印に絞り、全g数を押し込まない。cell全体を44px以上の押下領域にし、tapで選択日の詳細を下へ表示。数字一覧モードも用意し、全日のg数をスクリーンリーダー/縦リストで確認可能にする。未記録のハイフン、保留の?、未同期の時計等を色と文字で区別する。

全体範囲外には「不足側/超過側/混在」を添える。proteinが少し上回っただけで危険色/過剰警告を出さない。「設定目標との比較」「DRIの参考比較」「記録品質」「参考行動」は別の見出しにする。

iPadはカレンダーと選択日を2カラム、iPhoneは1カラム。表を横スクロールさせて基本情報を探させない。月に目標がない日も空白にせず「当時の目標なし」と分かる。

## 4. Nutrition / 週間

月曜〜日曜の期間とtimezone、前/次週、今週へ戻る操作を上部に置く。摂取評価の次週移動は現在週までとし、未来の計画設定はSettingsで扱う。

主表示は「記録合計 / 週間計画」「完全記録N/7日」「対象栄養素の判定可能N/7日」。energy/PFCの差分は、完全記録期間と週間の途中経過を分けて表示する。日別推移は空白を0として繋がず、部分日は既知小計として異なる記号にする。

参考調整量を表示できないときも画面は成立させる。保留理由、将来日の通常目標、確認すべき記録へのリンクを出す。週不足を「食べるノルマ」にしない。残り日数と「本日入力中」を別に示す。

「7日間の観察平均」は既存栄養詳細へのリンクとして残す。週目標残量の隣へ同じ平均値を置いて意味を混ぜない。

## 5. Nutrition / 栄養詳細

標準29を「エネルギー・PFC関連」「ミネラル」「ビタミン」にグループ化し、sodiumは内部管理の詳細展開へ。現行の既知量、記録完了日の平均範囲、基準との成立する比較、見直し、食品内訳を残す。

DRIのない糖質/コレステロールは量と「一般の基準なし」。新codeの欠損が多い過去期間も、捏造した基準到達ゲージを作らない。A/E/B6/Mg/folateの形態・scope不明は基準値の説明と保留理由を展開できるようにする。

欠損項目の修正は現在Catalogの編集と過去食事の訂正を区別する。「食品を編集しても過去の記録値は変わらない」を編集導線に添え、既存void＋replaceへ案内する。

## 6. Body

上部は最新実計測（測定日付き）、7日平均（件数付き）、任意目標体重、追加ボタン。30/90日切替の下に体重/体脂肪の系列切替と数値一覧を置く。未計測の間を実計測として補間しない。

フォームは日付、体重、任意体脂肪、詳細内に任意時刻・出典。1日1件制約があるため同日追加は既存編集へ。過去記録をtapして編集/削除でき、最新計測削除でprofileが変わる場合はその具体的な影響を確認に表示する。

履歴0件は「まだ計測記録がありません」。既存profile値があれば「プロフィールの単一値」と日付を示すが、グラフへ実計測点として追加しない。「確認して1件登録」だけを本人の任意操作として提供する。

「プロフィールへの反映」はmodeと現在の出典を表示する。profileの手動値と最新計測が違う場合も隠さない。下部に同じ期間の栄養達成日数を並べるが、因果の線や減量成功スコアを付けない。

## 7. Settings / 食事目標

profileから独立した画面または設定サブメニューにする。

    設定方法 [カスタム / 体格から参考 / training・rest]
    開始日
    kcal
    P%  F%  C%  合計100.00%
    自動算出g（読み取り専用）
    fiber下限 / salt上限
    PFC許容幅 / kcal許容幅
    split時: 曜日予定と2つのvariant
    参考計算の式・採用元
    [変更内容を保存]
    有効日付き履歴 / 将来予定の取消

合計100%になるよう他比率を黙って変更しない。数値キーボード、明確なinline error、保存前のg数・開始日確認を用いる。過去版は読み取り専用。「今日から変更」は過去全期間の編集を意味しない。

exportはformat、CSV粒度、開始/終了日を選ぶ。未同期件数を既存同様に示し、サーバー保存済みが出力対象であることを説明する。Account削除は既存の再認証と安全な境界を維持する。

## 8. 転送導線

Today/Historyの食事全体と食品行、Catalog/Product/Batchの詳細に「カロミルへ転送」を置く。通常の食事登録後に自動で開かない。

出力前に「食事記録全体」「この食品の実際の摂取量」「ライブラリの指定量」のどれかを明示。Batchの1食/全量を切替えると対象量と数値を再プレビューする。

プレビューはbasic7/all29、既知項目/省略項目、出典品質、PNG保存、共有、メニュー名コピーを提供する。基本7を既定とし、all29には外部OCR未検証と表示。共有後の「カロミルで登録を確認した」は別の手動操作。詳細は[転送設計](06-transfer-export-body.md)。

## 9. 全画面の受け入れ条件

- 320/360/390/430px、iPad縦横、safe area、キーボード表示、文字拡大でbody全体に横overflowがない。
- 主要touch targetは44px以上。5タブは等幅、safe-area-inset-bottomを考慮。
- 色だけに依存しない。%とg、目標差とDRI、既知分と完全量を読み上げでも区別。
- loading、error、未記録、全不明、目標なし、未同期、競合、offline、空の完了日を別fixtureで検証。
- 実iPhoneでPNG保存/共有/clipboardを確認する。WebKit emulatorの成功を実機合格と呼ばない。
- SleepとToday睡眠失敗時の栄養入力維持、History訂正、Chat導線を回帰。
- カロミルのロゴ・商標画像・画面素材・固有のUIを複製しない。独自の既存デザインを使用する。
